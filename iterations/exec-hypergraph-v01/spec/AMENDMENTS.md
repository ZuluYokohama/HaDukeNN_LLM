# Implementation additions and evaluation scope

## 2026-11-25 — Engineering controls added during development

The original `PREREGISTRATION.json` remains byte-for-byte unchanged. Its pilot grid, semantic comparisons, and excluded claims remain in force.

During implementation, finite scope, revision, source, command, and receipt limits were made explicit. Focused regression tests were added for those limits and for defects identified in independent code review. These are engineering acceptance controls developed with the implementation, not newly preregistered scientific effects.

A reversible byte-to-overlapping-span module was also added. Its reconstruction, bounded-candidate, ordered-incidence, and causal-prefix invariants are evaluated separately from the frozen relational task grid. No tokenizer or learned-model superiority claim is made.

The full CPU timing run is descriptive. Its three repeats per workload are first averaged within each workload/seed block. The graph kernel emits richer audit records than the ordinary baselines. Therefore the timing table is not an equal-audit performance contest, and no p-value or tenfold-capability verdict is inferred from it.

All reported confirmation results must identify the actual code and specification hashes. Earlier development runs are retained separately and are not relabeled as untouched holdout results. These publicly specified synthetic engineering cases are reusable regression inputs, not a concealed model-generalization test set.
